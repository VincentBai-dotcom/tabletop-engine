---
title: "Configuration"
description: "Configure the game and publish source in tableverse.config.ts."
---

Create `tableverse.config.ts` in your project root and export `defineConfig(...)` as the default value.

```ts
import { defineConfig } from "@tableverse-kit/config";
import { game } from "./engine/src/game.ts";

export default defineConfig({
  game,
  publish: {
    engine: {
      root: "./engine",
    },
    frontend: {
      root: "./client",
      buildCommand: "npm run build",
      outDir: "dist",
    },
  },
});
```

`defineConfig` returns the object unchanged. Its purpose is type checking and editor completion.

## Top-level fields

| Field | Required | Description |
| --- | --- | --- |
| `game` | Yes | A built game definition from `GameDefinitionBuilder`. |
| `publish` | For dev and upload | Engine and frontend source build settings. |

You can use `tvk validate` without `publish`. `tvk dev` uses `publish.frontend.root` to start the frontend. `tvk upload` packages the project root and sends the publish settings to Tableverse.

## Engine publish settings

```ts
engine: {
  root: "./engine",
}
```

`root` is the engine workspace directory, relative to `tableverse.config.ts`.

Point it at the engine workspace source. Tableverse creates the sandbox bundle.

## Frontend publish settings

```ts
frontend: {
  root: "./client",
  buildCommand: "npm run build",
  outDir: "dist",
}
```

- `root` is the frontend source directory, relative to the config file.
- `buildCommand` runs inside that source directory on Tableverse.
- `outDir` is the static build output, relative to the frontend root.

The CLI excludes `outDir` from upload because the platform recreates it.

## Workspace and lockfile

Keep `tableverse.config.ts`, `package.json`, and `package-lock.json` in the project root. The root `package.json` declares the engine and client as npm workspaces:

```json
{
  "private": true,
  "workspaces": ["engine", "client"]
}
```

The client can depend on the engine workspace for compile-time game types:

```json
{
  "dependencies": {
    "token-race-engine": "0.0.0"
  }
}
```

The project source archive includes the root lockfile and both workspaces, so Tableverse installs one dependency graph before building the engine and frontend.

## Config discovery

Keep one `tableverse.config.ts` in the project root. The CLI searches the current directory and its parents until it finds that file.

You can run `tvk` from the project root, `engine/`, `client/`, or another directory inside the project. Relative `root` paths resolve from the project root.

<Note>
  `tvk upload` stores game identity in `.tableverse/game.json`. `TABLEVERSE_GAME_ID` overrides the saved identity.
</Note>
