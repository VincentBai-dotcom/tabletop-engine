---
title: "tvk dev"
description: "Start the local rules server and frontend."
---

Start the complete development environment from the generated project root:

```bash
npm run dev
```

This loads `tableverse.config.ts`, starts the rules server at `http://localhost:5100`, and runs the frontend's `dev` script from `publish.frontend.root`.

Create your frontend client:

```ts
import { createTableverseClient } from "@tableverse-kit/client";
import type { executor } from "token-race-engine";

const client = createTableverseClient<typeof executor>({
  viewer: "p1",
  players: ["p1", "p2"],
});
```

## Options

```text
tvk dev

Optional flags:
  --port <number>
```

Use another port when `5100` is busy:

```bash
npx tvk dev --port 5200
```

## Local session behavior

- The first client connection initializes the game.
- Every client connects to the same in-memory state.
- Each connection can choose a `viewer` and receives that player's safe view.
- Accepted commands send fresh snapshots to all connected clients.
- Domain and stage events are delivered to connected clients.
- Restarting the command clears the session.

Restart `tvk dev` after changing engine source. The command loads the game definition when it starts.

<Warning>
  `tvk dev` is for local authoring only. It has no authentication or persistence and is not a production server.
</Warning>

## Troubleshooting

If the client remains on `connecting`:

1. Confirm `tvk dev` printed its listening URL.
2. Confirm the frontend uses the same port.
3. Check that setup input matches the schema in your game definition.
4. Restart the server to clear a session initialized with old input.

If config loading fails, confirm the project root contains `tableverse.config.ts`. Run `tvk validate` from the same directory to check the game definition.
