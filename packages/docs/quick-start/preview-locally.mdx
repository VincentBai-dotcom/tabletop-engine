title: "Preview locally"
description: "Run your rules locally and connect your frontend."
---

Run the rules server and frontend in separate terminals.

<CodeGroup>
```bash Rules server
pnpm dev:server
```

```bash Frontend
pnpm dev:web
```
</CodeGroup>

`pnpm dev:server` runs `tvk dev` from the engine package. It loads `engine/tableverse.config.ts` and listens at `http://localhost:5100` by default.

The scaffold connects with `createDevClient` during development:

```ts
import { createBridgeClient, type TableverseClient } from "@tableverse-kit/client";
import { createDevClient } from "@tableverse-kit/client/dev";
import type { executor } from "token-race-engine";

type Game = typeof executor;

function connect(): TableverseClient<Game> {
  if (import.meta.env.DEV) {
    const url = import.meta.env.VITE_TVK_DEV_URL ?? "http://localhost:5100";
    return createDevClient<Game>(url, { viewer: "p1" });
  }

  return createBridgeClient<Game>();
}
```

The local client initializes one in-memory session, receives a player-safe view, and sends commands over HTTP. It updates all connected browser windows after an accepted command.

## Try multiple players

The first connection initializes the session, so give it the full roster. Other browsers pick a different `viewer` from that roster:

```ts
// First client — initializes the match
createDevClient<Game>("http://localhost:5100", {
  viewer: "p1",
  players: ["p1", "p2"],
});

// Second browser — same match, different viewer
createDevClient<Game>("http://localhost:5100", {
  viewer: "p2",
});
```

If your game defines setup input, pass it from the first client too:

```ts
const client = createDevClient<Game>("http://localhost:5100", {
  viewer: "p1",
  players: ["p1", "p2"],
  setupInput: { targetScore: 10 },
});
```

<Note>
  The local server keeps state in memory. Restarting `tvk dev` starts a new session.
</Note>

## Change the port

```bash
pnpm -C engine exec tvk dev --port 5200
```

Set `VITE_TVK_DEV_URL=http://localhost:5200` for the frontend as well.
